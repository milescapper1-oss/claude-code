# data/contacts.json + data/conferences.json

Unlike the rest of `data/` (scraper output, regenerated by running the
scrapers), these two files are **manually researched**, compiled via web
search on 2026-07-15, and checked into git because they can't be
regenerated by any script in this repo.

## Methodology

Every record was built from a public, attributable, non-LinkedIn source:
official company/investor press releases, government economic-development
announcements, ISPE/PDA/ASME industry-body listings, university and
alumni-magazine profiles, and official French/UK company-registry filings.
Each record's `source_url` and `source_note` field says exactly where it
came from — treat unsourced claims as unverified.

**Explicitly excluded** during research, and left out of these files on
purpose:

- Two names that surfaced attributed to Wilson, NC leadership ("Pete G.",
  "Eva R.") — the truncated-last-name format is the signature of a gated
  sales-intelligence preview (ZoomInfo/RocketReach/Apollo-style), not a
  primary source, likely itself scraped from LinkedIn.
- "Karen Hennessy" (Senior Director, Engineering & Technology, lead on the
  BioCork 3.2 expansion) — an excellent functional match, but the only
  source found was a LinkedIn post. Not included on principle: this
  project's whole premise is not laundering LinkedIn data through other
  tools.
- The Val-de-Reuil, France site — surfaced in search but now operates
  under the **Kenvue** brand (spun off from J&J Consumer Health in 2023),
  not current J&J.

## Known gaps / staleness risk

- `date_found` is when the research was done, not when the underlying fact
  was true — some sources (e.g. the IDA Ireland press release for Leila
  Schwery-Bou-Diab) are from 2022 and the person may have since moved
  roles.
- Coverage is uneven by design: sites with recent headline capital-project
  announcements (Wilson NC, Spring House PA, Jacksonville FL, Ringaskiddy
  Cork, Geel/Beerse Belgium, Leiden NL, Schaffhausen CH) turned up named
  executives; smaller/established sites without recent news (Danvers MA,
  Fort Washington PA, Skillman/Somerset/Bridgewater NJ, Athens/Cornelia GA,
  Zug/Turnhout, High Wycombe/Gargrave UK) did not — that's a real signal
  about where public information exists, not an oversight to "fix" by
  guessing names.
- `meet_at` is populated only where a specific 2026 conference appearance
  was confirmed for that person; see `conferences.json` for the fuller
  event calendar (including venues with strong site-density signal but no
  confirmed named speaker yet, e.g. the ISPE Delaware Valley Chapter
  symposium).

## Schema

`contacts.json` / `contacts.csv`: `name, title, org, site, region,
function, source_url, source_note, meet_at, date_found, canonical_site,
canonical_title` — the last two are computed by running the raw `site`/
`title` fields through `dedup.py`'s `dedup_records()`, same as scraper
output would be.

`conferences.json` / `conferences.csv`: `name, dates, location,
jnj_confirmed, notes`.
